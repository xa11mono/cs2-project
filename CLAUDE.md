# CLAUDE.md — правила для работы с проектом

Полное описание — [ARCHITECTURE.md](ARCHITECTURE.md). Перед правкой прочитать раздел «Правила внесения правок».

## Главное правило: все правки — в хозяина

- **Любая правка вносится в уже существующий код** — в модуль-хозяин функции или механики. Найти хозяина:
  домен по папке (`js/<домен>/`), `docs/LAYERS.md`, в браузере `CS2.chain('имя')`.
- **Не создавать независимых функций, слоёв, файлов и модулей**, которые дублируют, обходят или переопределяют
  существующее: никаких `vNNN-fix.js`, никаких новых `CS2.patch` поверх чужой функции ради исправления, никаких
  копий функции «с изменениями», никаких вторых функций, делающих то же самое.
- Вспомогательная логика — внутри модуля-хозяина. Новый модуль — только для действительно новой подсистемы без
  хозяина; тогда новые функции живут в нём.
- Ручные обёртки `window.X = function () { … old … }` запрещены; временная подмена на один вызов — `CS2.swap`.
- Числа баланса — в `CS2Config` (`js/core/config.js`), периодические задачи — `CS2Loop.every`, места в рейтинге —
  `CS2Rank`, уступка браузеру в долгих циклах — `CS2Yield`.

## Ветки

- Ветка под версию называется `v` + номер версии: `v145`, `v146`. Номер — следующий после текущего `BUILD`
  в `js/boot/manifest.js` (сейчас 144); в той же ветке `BUILD` поднимается до этого номера.
- Тестовая (пробная) ветка той же версии — с буквой: `v145a` (альфа), `v145b` (бета), `v145c` и так далее.
- Других имён веток не создавать; готовая версия попадает в `main` из ветки `vNNN`.

Проверка: `npm test` (в т. ч. `tests/v144-layers.test.js` — число слоёв `CS2.patch` не растёт, слои мимо ядра
запрещены), `npm run analyze`.
