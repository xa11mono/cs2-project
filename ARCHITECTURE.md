# Архитектура CS2 Manager

Игра — статическая страница: `index.html` открывается из файла, без сервера и без сборки. Весь код — обычные
скрипты, которые общаются через глобальные объекты (`teams`, `seasonState`, `transferState`, `window.V31`, `HS`…).
Этот документ — как устроен проект и **как вносить правки, чтобы они не накладывались на старые вслепую**.

## Карта проекта

```
index.html              разметка; стили и скрипты сам не перечисляет
js/boot/manifest.js     ЕДИНСТВЕННЫЙ список модулей (CSS и JS) в порядке загрузки + версия BUILD
js/boot/loader.js       подключает стили, затем по команде store.js — скрипты по порядку
js/boot/store.js        сохранение в IndexedDB (большие ключи), запускает игру после чтения сейва
js/core/                ядро: kernel (CS2.patch, шина событий, карта слоёв), scheduler (CS2Loop, CS2Yield),
                        config (CS2Config — все числовые параметры), ranking (CS2Rank), сохранения, автосейв
js/data/                справочники: игроки, составы 2026, EMDB, контуры кубков, иконки, фразы
js/base/                исходная игра (game.js — модель команд, турниров, матчей) и её ранние надстройки
js/calendar/            игровое время, календарь, перемотка
js/competition/         турниры Tier-1/2/3, Мейджоры и путь к ним, рейтинги VRS/HLTV, жеребьёвка, шоу-события
js/match/               движок матча: исход, раунды, вето, тактика, эфир, режим зрителя
js/radar/               2D-симуляция раунда (радар Mirage)
js/rosters/             составы и рынок ИИ: трансферы, контракты, сила и стоимость игроков, развитие, карьеры
js/career/              режим менеджера: клуб, финансы, совет, штаб, тренировки, разговоры, состав, сделки
js/awards/              кубки, награды сезона, достижения
js/media/               новости, слухи, паблики, комментарии, сообщество
js/fan/                 Pick'Em, стикеры, капсулы, значки, ставки
js/portal/              интерфейс портала «HLTV»: страницы, навигация, оболочка «Арена»
css/<домен>/            стили по тем же доменам (порядок каскада — в манифесте)
assets/, fonts/         картинки, логотипы, шрифты (в коде больше нет base64-вставок)
tests/                  тесты (node tests/run-all.js), tests/lib/project.js — общие помощники
tools/build/            analyze.mjs (карта слоёв), build.mjs (релиз в dist/), extract_assets.py
docs/                   отчёты, docs/LAYERS.md (кто какую функцию расширяет), docs/changelog/ — история версий
```

Папка — это домен, а не версия. Префиксы `v29-`, `v84-` и т. п. из имён убраны (соответствие старых имён новым —
`tools/build/layout.tsv`; старые имена встречаются в истории `docs/changelog/`).

## Как загружается игра

1. `<head>`: `manifest.js` → `loader.js` подключает все стили из манифеста (синхронно, без мигания).
2. Конец `<body>`: `store.js` читает большие ключи сейва из IndexedDB в память и подменяет для них `localStorage`
   (игра по-прежнему пишет `localStorage` синхронно), затем вызывает `CS2Boot.run()`.
3. `loader.js` добавляет скрипты манифеста по порядку (`async=false`). После каждого файла ядро отмечает, какие
   глобальные функции он объявил или заменил — так строится карта слоёв.

**Порядок в манифесте — это порядок слоёв.** Модуль ниже может расширять функции модулей выше.

## Правила внесения правок

### 1. Сначала посмотрите, кто уже трогает функцию

- `docs/LAYERS.md` — статическая карта: какая глобальная функция расширяется какими модулями (обновить:
  `npm run analyze`).
- В игре, в консоли браузера: `CS2.chain('processTransferMarket')` — все слои сверху вниз (верхний срабатывает
  первым), `CS2.layers()` — все функции, у которых больше одного слоя, `CS2.modules()` — модули и время загрузки.

### 2. Правка поведения — в модуле-владельце

Если функция или механика уже живёт в каком-то модуле, **меняйте этот модуль**, а не добавляйте новый слой сверху.
Новый файл «v145-fix.js», который переопределяет чужую функцию, — ровно то, из-за чего правки накладывались друг
на друга. Владелец обычно очевиден по домену; если функцию расширяют несколько слоёв, правьте тот, чья логика
меняется (по `CS2.chain`).

### 3. Расширение чужой функции — только через `CS2.patch`

```js
// было (так больше не писать):
const old = window.playerWillAccept;
window.playerWillAccept = function (...a) { if (особый случай) return false; return old.apply(this, a); };
try { playerWillAccept = window.playerWillAccept; } catch (e) {}

// стало:
CS2.patch('playerWillAccept', base => function (player, from, to) {
  if (особый случай) return false;
  return base.apply(this, arguments);
}, { id: '__myLayer' });          // id — защита от двойного подключения; слой виден в CS2.chain
```

`CS2.patch` сам переносит служебные свойства прежних слоёв, ставит метку `id`, обновляет глобальную привязку и
регистрирует слой. Опции: `id` — защита от двойного подключения, `ifExists: true` — нет такой функции → тихо
пропустить, `optional: true` — база может отсутствовать (полная замена: `CS2.patch('X', () => новаяФункция, { optional: true })`).

Все слои игры (216 на старте) подключены через `CS2.patch`. Тест `tests/v144-layers.test.js` падает, если в игре
появился слой мимо ядра — ручную обёртку `window.X = function () { … old … }` писать нельзя.

Временная подмена на время одного вызова — не слой, для неё `CS2.swap`:

```js
const ok = CS2.swap('playerWillAccept', () => true, () => applyPlayerTransfer(from, to, p, 'договорённость'));
// прежняя функция возвращается в finally — даже если вызов бросил исключение
```

### 4. Реакция на события — подписка, а не обёртка

Если модулю нужно «что-то сделать после X», подпишитесь на событие вместо обёртывания чужой функции. Все события
игры (`v29Emit(type, data)`) приходят в шину ядра:

```js
CS2.on('transfer', ({ player, from, to, reason }) => { … });   // подписка; CS2.off / CS2.once — так же
CS2.emit('sponsor-signed', { team, sponsor });                 // своё событие — в модуле-владельце
```

Типы событий игры: `transfer`, `signing`, `release`, `bench`, `loan`, `loan-return`, `promotion`, `standin`,
`retire`, `coach`, `extension`, `negotiation`, `rumor-denied`, `roster-lock`, `window-open`, `window-close`,
`tournament`, `parallel`, `major-preview`, `season-end`, `breakout`, `career-event`, `career-goal`. Ошибка в
подписчике не ломает остальных (ловится и пишется в консоль).

### 5. Числа — в `CS2Config`

Любой порог, вес или коэффициент баланса — параметр в `js/core/config.js` (`CS2Config.get('ключ', поУмолчанию)`),
с пометкой источника. Так баланс меняется в одном месте, а горячий код может кешировать производные значения по
`CS2Config.version`.

### 6. Периодические задачи и долгие циклы

- Периодическая задача — `CS2Loop.every(fn, мс, 'метка')` (один общий таймер с бюджетом на тик), не `setInterval`.
- Долгий цикл (перемотка, архив, пересчёт) уступает браузеру через `await CS2Yield.maybe(10)` или
  `await CS2Yield.frame()`. Не пишите свои «yield frame» на `requestAnimationFrame`: `CS2Yield` перерисовывает не
  чаще раза в 50 мс, а в остальное время уступает мгновенно — перемотка из-за этого в разы быстрее.
- Место команды в рейтинге — `CS2Rank.of(команда | имя)`, список по местам — `CS2Rank.pro()` (с кешем), а не
  `teams.filter(...).sort(...)` в каждом вызове.

### 7. Новый модуль

1. Файл в папке своего домена с понятным именем (`js/career/sponsor-events.js`), в шапке — что и зачем делает.
2. Одна строка в `js/boot/manifest.js` в нужном месте порядка; при изменении поведения — увеличить `BUILD`
   (сбрасывает кэш браузера у всех файлов).
3. Стили — `css/<домен>/<имя>.css`, тоже строкой в манифесте. Значения интерфейса — по `DESIGN.md`.
4. Тест в `tests/` (см. ниже). Запись в `docs/changelog/`.

### 8. Сохранения

- Большие ключи (`cs2_season_state_v61`, `cs2_season_teams_v61`, `cs2_transfer_market_v1`, `cs2_player_awards_v1`,
  `cs2_news_v1`, `cs2_fan_v1`) живут в IndexedDB (`js/boot/store.js`), остальное — в `localStorage`.
- `saveTeams()/saveSeasonState()/saveTransferState()` можно вызывать сколько угодно: запись объединяется
  (`js/core/save-coalesce.js`, не чаще раза в 4 с, при закрытии — сразу).
- При закрытии/перезагрузке страницы незаписанные ключи дополнительно копируются синхронно в `localStorage`
  (транзакцию IndexedDB браузер может оборвать) — при следующем запуске берётся более свежая версия.
- Новое поле состояния кладите внутрь `seasonState`/`transferState` под своим ключом и создавайте лениво
  (`seasonState.myFeature = seasonState.myFeature || {…}`) — старые сейвы должны открываться.

## Тесты и инструменты

| Команда | Что делает |
| --- | --- |
| `npm run setup` | ставит инструменты сборки (`tools/build`: esbuild, acorn) |
| `npm test` | все тесты параллельно (`node tests/run-all.js -j 3 [фильтр]`), логи упавших — `tests/.logs/` |
| `npm run analyze` | проверка модулей и карта слоёв → `docs/LAYERS.md` |
| `npm run build` | релиз в `dist/` (модули минифицированы, стили в одном файле); `dist/index.html` открывается из файла |
| `npm run check` | анализ + пробная сборка без записи |

Браузерные тесты используют Playwright (Chromium). Помощники — `tests/lib/project.js`:
`pageSources()` (разметка + список модулей манифеста), `manifest()`, `chooseStart(page, 'history'|'zero')` —
дождаться окна новой игры и выбрать режим (не используйте фиксированные паузы: под нагрузкой они ненадёжны).
Долгая проверка мира — `node tests/v90-long-sim.test.js [недель]`, автопилот карьеры — `tests/career-autoplay.js`.
