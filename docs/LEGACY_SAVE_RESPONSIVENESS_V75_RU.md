# v75 — устранение периодических зависаний на старых сохранениях

## Первопричина

При записи архива сеток локальный кэш собирался квадратичным способом: на каждой итерации сериализовался весь объект, который уже содержал все предыдущие турниры. На длинной карьере это создавало большие синхронные задачи JavaScript и визуальные паузы.

Дополнительная постоянная нагрузка приходилась на проверку невыплаченных призовых параллельных турниров: каждые четыре секунды экспортировался и обходился весь архив, даже если он не менялся.

## Исправления

- Кэширование архива выполняется одним проходом после сортировки: размер каждой новой записи считается отдельно, полная сериализация объекта выполняется один раз.
- В архивном хабе появился журнал ревизий и изменившихся ID (`hubArchiveChangesSince`, `hubArchiveGet`).
- Проверка призовых параллельных турниров выполняется только при изменении архива; при неизменной ревизии работа почти бесплатна.
- Маркер `v31paid` сохраняется в архив, предотвращая повторную выплату при перезапуске.
- Read-only календарные рекомендации больше не создают/инициализируют слои игроков для каждой команды в старом сохранении.
- Сохранены изменения v74: часы отделены от тяжёлых частей календаря, архивная статистика кэшируется по ревизии, новости используют лёгкий индекс матчей, сериализация и таймеры работают реже.

## Диагностика в браузере

В Chrome/Edge открой DevTools → Console и выполни:

```js
window.CS2RuntimePerformance.snapshot()
```

В `recent` показаны длительные задачи (Long Tasks) и источник, если браузер его раскрывает. Также доступен `window.CS2SimulationPerf.lastBatch` после пакетной перемотки.

## Безопасность данных

Патч не удаляет архивные турниры, матчи или историю и не меняет формулы результатов. Локальный `localStorage`-кэш по-прежнему может быть ограничен размером браузера, но полная история остаётся в памяти/IndexedDB согласно прежней схеме.
