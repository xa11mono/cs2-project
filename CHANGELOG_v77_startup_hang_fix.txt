CS2 Manager v77 — исправление зависания запуска больших/старых сохранений

Причины, устранённые в этой версии:
- Удалена синхронная полная сериализация teams в localStorage через 2,5 секунды после старта. На больших сохранениях она могла совпадать с первым полным автосейвом и миграцией архива и приводить к RESULT_CODE_HUNG в Chromium.
- Миграция строковых названий команд использует заранее построенные Map-индексы вместо повторного Object.entries().find() для каждой записи.
- Составы EMDB для строковых записей подготавливаются в общем проходе загрузки команд, без повторной генерации игроков внутри нормализатора.
- Добавление отсутствующих EMDB-команд использует Set имён, а не повторный линейный просмотр всего массива для каждой записи.
- Удалён дублирующий полный проход ensurePlayerLayer по всем командам при старте.
- Перенос архива HLTV в IndexedDB разбит на пакеты по 20 записей с уступкой event loop между транзакциями.
- Пока миграция IndexedDB выполняется, полный архив не сериализуется синхронно обратно в localStorage. Старый локальный ключ удаляется только после подтверждённого commit.
- Autosave больше не дублирует крупные canonical localStorage-ключи в localStorageSnapshot, поскольку эти данные уже записаны в отдельных верхнеуровневых полях JSON-сейва.

Совместимость:
- Поддерживается старый формат команд, где запись могла быть строкой.
- Составы существующих команд и их сохранённая история не заменяются.
- Полный архив не удаляется до подтверждённой записи в IndexedDB.

Проверки:
- 32 standalone регрессионных теста пройдены.
- Синтаксис 90 JS-файлов проверен через node --check.
- Нормализация 3000 строковых названий команд в тестовом сценарии: 19 мс в среде сборки.
- Реальный запуск в браузере пользователя и импорт его конкретного сейва не проверены; Playwright отсутствует в среде.
